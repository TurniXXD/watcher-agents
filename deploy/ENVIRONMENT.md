# Production environment inventory

Production configuration is intentionally split across GitHub and the VPS.

## GitHub environment variables

These non-sensitive values belong in the GitHub environment named `production`:

| Name              | Required | Detailed meaning                                                                                                                                                                                                                                                                                                                     |
| ----------------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `DEPLOY_PATH`     | Yes      | Absolute VPS directory containing the production Compose file, deploy script, release state, runtime environment files, and backups; normally `/opt/watcher`. The SSH deployment account must be able to read and write it.                                                                                                          |
| `DEPLOY_ENV_FILE` | Yes      | Absolute path to the rendered, non-secret Docker Compose interpolation file on the VPS; normally `/opt/watcher/deploy/runtime/compose.env`. The workflow passes it to `docker compose --env-file`. Generate it with `deploy/render-env.sh` or copy the preset; application secrets remain in the separate mode-`0600` runtime files. |
| `TS_TAG`          | No       | Tailscale ACL tag assigned to the ephemeral GitHub Actions identity. Defaults to `tag:ci`; the tailnet policy should allow this tag to reach only the Watcher VPS SSH port.                                                                                                                                                          |

## GitHub environment secrets

| Name                 | Required | Detailed meaning                                                                                                                                                                           |
| -------------------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `DEPLOY_HOST`        | Yes      | Tailscale IPv4/IPv6 address or MagicDNS hostname of the Watcher VPS. It is used as the SSH destination after the CI runner joins the tailnet.                                              |
| `DEPLOY_USER`        | Yes      | Dedicated non-interactive VPS account used for SSH deployment. It needs Docker access and permissions for `DEPLOY_PATH`, but should not be a general administrator account when avoidable. |
| `DEPLOY_SSH_KEY`     | Yes      | Private half of the dedicated deployment SSH key, including its complete multiline OpenSSH encoding. The matching public key belongs only in the deployment account's `authorized_keys`.   |
| `DEPLOY_KNOWN_HOSTS` | Yes      | Independently verified `known_hosts` entry for the VPS SSH host key. This pins server identity and must not be generated by blindly trusting `ssh-keyscan` during the same deployment.     |
| `DEPLOY_PORT`        | No       | TCP port of the VPS SSH service. Defaults to `22`; the Tailscale ACL and host firewall must permit the selected port from `TS_TAG`.                                                        |
| `GHCR_USERNAME`      | Yes      | GitHub account or machine-user name used by Docker on the VPS when pulling the private Watcher image.                                                                                      |
| `GHCR_TOKEN`         | Yes      | GitHub Container Registry credential used only to pull images on the VPS. For a classic PAT, grant `read:packages` only; repository access must also cover the image when it is private.   |
| `TS_OAUTH_CLIENT_ID` | Yes      | Client ID of a Tailscale OAuth client authorized to create an ephemeral tagged CI node. It is transport authentication, not an application credential.                                     |
| `TS_OAUTH_SECRET`    | Yes      | Secret for the Tailscale OAuth client. Configure the OAuth client and tag ownership with the least privileges needed for the ephemeral CI identity; do not reuse a personal auth key.      |

`GITHUB_TOKEN` publishes images from the workflow and is provided automatically. Do not create a separate write token for publishing.

| `DISCOVERY_MOVE_THRESHOLD_PERCENT`                     | No       | Minimum absolute percentage move for a top-gainer/loser observation to remain a discovery candidate. Positive number up to `1000`, default `4`; both gains and losses qualify.                                                                                                                                                                                                                                                                        |
| `DISCOVERY_MIN_PRICE`                                  | No       | Minimum quoted share price accepted by discovery. Non-negative number, default `2`; this is a quality/liquidity filter, not an investment rule.                                                                                                                                                                                                                                                                                                       |
| `DISCOVERY_MIN_VOLUME`                                 | No       | Minimum current snapshot share volume accepted by discovery. Non-negative integer, default `100000`; Alpha Vantage's mover snapshot does not supply historical average volume for this filter.                                                                                                                                                                                                                                                        |
| `DISCOVERY_MIN_DOLLAR_VOLUME`                          | No       | Minimum approximate liquidity calculated as current price × current volume. Non-negative number, default `1000000`; candidates below it are discarded before SEC resolution or deeper scanning.                                                                                                                                                                                                                                                       |
| `DISCOVERY_MAX_CANDIDATES`                             | No       | Maximum qualifying companies activated for investigation from one market-wide scan. Integer `1..100`, default `10`; lowering it bounds SEC/source traffic and follow-up work.                                                                                                                                                                                                                                                                         |
| `DISCOVERY_SUPPORTED_EXCHANGES`                        | No       | Comma-separated SEC exchange names eligible for automatic discovery, default `Nasdaq,NYSE,NYSE American`. Matching uses the issuer exchange returned by SEC; manual watchlist entries are not removed by this filter.                                                                                                                                                                                                                                 |
| `DISCOVERY_EXCLUDE_OTC`                                | No       | Boolean `true`/`false`, default `true`. When enabled, automatic discovery rejects issuers whose SEC exchange metadata indicates OTC trading; it does not disable manually added symbols.                                                                                                                                                                                                                                                              |
| `DISCOVERY_INVESTIGATION_MINUTES`                      | No       | Lifetime of a temporary `INVESTIGATE/HIGH_RESOLUTION` state when an unexplained candidate or anomaly is found. Integer `30..1440`, default `90`; without confirming material evidence the company returns to discovery after expiry.                                                                                                                                                                                                                  |
| `DISCOVERY_HIGH_RESOLUTION_INTERVAL_MINUTES`           | No       | Interval for follow-up SEC, issuer, news, price, and optional Quiver-insider checks while a company is in high-resolution or event mode. Integer `1..120`, default `5`; shorter intervals increase provider traffic.                                                                                                                                                                                                                                  |
| `DISCOVERY_EVENT_MODE_MINUTES`                         | No       | Duration of temporary `EVENT_MODE` polling after a material event is confirmed. Integer `15..1440`, default `120`; afterwards a watched company returns to its normal monitoring mode while retaining its watch state.                                                                                                                                                                                                                                |
| `DISCOVERY_WATCH_DAYS`                                 | No       | Number of days an automatically promoted company remains in `WATCH` after material evidence. Integer `1..365`, default `14`; a newer material event can extend it, otherwise it returns to discovery on expiry.                                                                                                                                                                                                                                       |
| `DEFAULT_TIMEZONE`                                     | No       | IANA timezone assigned to newly created watcher schedules and used when `/schedule` omits one. Default `Europe/Prague`; existing watcher rows retain their persisted timezone until changed through Telegram.                                                                                                                                                                                                                                         |
| `LOG_LEVEL`                                            | No       | Structured Pino log verbosity for all bots, normally `info`. Use `debug` temporarily for per-source/per-item diagnostics; avoid verbose production logging longer than needed.                                                                                                                                                                                                                                                                        |
| `COMPOSE_PROJECT_NAME`                                 | No       | Docker Compose project/resource prefix. Default `watcher`, producing container names such as `watcher-postgres-1` and a project-scoped PostgreSQL volume. Changing it creates a separate Compose project and volume rather than renaming or reusing the existing database automatically.                                                                                                                                                              |

Example database URL:

```text
postgresql://watcher:URL_ENCODED_PASSWORD@postgres:5432/watcher
```

The render script writes separate least-privilege files so each bot receives only its own Telegram token. It creates them with mode `0600`.

## Values generated by the workflow

Do not configure these manually:

| Name              | Source and purpose                                                                                                                                                             |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `IMAGE_REGISTRY`  | Fixed by the workflow to `ghcr.io`; forms the registry part of the immutable production image reference.                                                                       |
| `IMAGE_NAMESPACE` | Lowercase GitHub repository owner generated by the workflow; forms the namespace in `ghcr.io/<namespace>/watcher:<tag>`.                                                       |
| `IMAGE_TAG`       | Exact successful Git commit SHA being deployed. It is deliberately immutable and replaces the previous value in `.release.env` only after migration and health checks succeed. |

They are written to `.release.env` on the VPS only after migrations succeed.
