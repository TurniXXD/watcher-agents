# Production environment inventory

Production configuration is intentionally split across GitHub and the VPS.

## GitHub environment variables

These non-sensitive values belong in the GitHub environment named `production`:

| Name              | Required | Meaning                                           |
| ----------------- | -------- | ------------------------------------------------- |
| `DEPLOY_PATH`     | Yes      | Absolute deployment directory on the VPS          |
| `DEPLOY_ENV_FILE` | Yes      | Absolute path to the VPS Compose environment file |
| `TS_TAG`          | No       | Ephemeral runner tag; defaults to `tag:ci`        |

## GitHub environment secrets

| Name                 | Required | Meaning                                       |
| -------------------- | -------- | --------------------------------------------- |
| `DEPLOY_HOST`        | Yes      | VPS Tailscale IP or MagicDNS hostname         |
| `DEPLOY_USER`        | Yes      | SSH deployment account                        |
| `DEPLOY_SSH_KEY`     | Yes      | Dedicated private SSH key                     |
| `DEPLOY_KNOWN_HOSTS` | Yes      | Independently verified OpenSSH host-key entry |
| `DEPLOY_PORT`        | No       | SSH port; defaults to `22`                    |
| `GHCR_USERNAME`      | Yes      | GHCR account used by Docker on the VPS        |
| `GHCR_TOKEN`         | Yes      | GHCR token with `read:packages`               |
| `TS_OAUTH_CLIENT_ID` | Yes      | Tailscale OAuth client ID                     |
| `TS_OAUTH_SECRET`    | Yes      | Tailscale OAuth client secret                 |

`GITHUB_TOKEN` publishes images from the workflow and is provided automatically. Do not create a separate write token for publishing.

## VPS render inputs

These values are consumed by `deploy/render-env.sh`; they do not belong in GitHub Actions:

| Name                          | Required | Recommended value or meaning                            |
| ----------------------------- | -------- | ------------------------------------------------------- |
| `POSTGRES_DB`                 | Yes      | `watcher`                                               |
| `POSTGRES_USER`               | Yes      | `watcher`                                               |
| `POSTGRES_PASSWORD`           | Yes      | Long random password                                    |
| `WATCHER_DATABASE_URL`        | Yes      | URL-encoded PostgreSQL URL using host `postgres`        |
| `STOCKS_TELEGRAM_TOKEN`       | Yes      | Stocks BotFather token                                  |
| `PUBLICATIONS_TELEGRAM_TOKEN` | Yes      | Publications BotFather token                            |
| `TELEGRAM_ALLOWED_USER_IDS`   | Yes      | Comma-separated numeric Telegram user IDs               |
| `OLLAMA_URL`                  | Yes      | Usually `http://host.docker.internal:11434`             |
| `OLLAMA_MODEL`                | Yes      | For example `qwen3:8b`                                  |
| `OLLAMA_KEEP_ALIVE`           | No       | Defaults to `5m`; use `0` to unload after every request |
| `OLLAMA_MAX_ITEMS_PER_RUN`    | No       | Defaults to `0`, meaning all new items                  |
| `OLLAMA_NUM_CTX`              | No       | Defaults to `4096`                                      |
| `OLLAMA_NUM_PREDICT`          | No       | Defaults to `768`                                       |
| `OLLAMA_RETRIES`              | No       | Defaults to `1`; maximum `2`                            |
| `OLLAMA_THINK`                | No       | Defaults to `false`                                     |
| `OLLAMA_TIMEOUT_MS`           | No       | Defaults to `120000`; maximum `180000`                  |
| `SEC_USER_AGENT`              | Yes      | Identifiable application name and administrator contact |
| `DEFAULT_TIMEZONE`            | No       | Defaults to `Europe/Prague`                             |
| `LOG_LEVEL`                   | No       | Defaults to `info`; use `debug` for per-item run logs   |
| `COMPOSE_PROJECT_NAME`        | No       | Defaults to `watcher`                                   |

Example database URL:

```text
postgresql://watcher:URL_ENCODED_PASSWORD@postgres:5432/watcher
```

The render script writes separate least-privilege files so each bot receives only its own Telegram token. It creates them with mode `0600`.

## Values generated by the workflow

Do not configure these manually:

| Name              | Source                              |
| ----------------- | ----------------------------------- |
| `IMAGE_REGISTRY`  | Fixed to `ghcr.io`                  |
| `IMAGE_NAMESPACE` | Lowercase GitHub repository owner   |
| `IMAGE_TAG`       | Exact successful release commit SHA |

They are written to `.release.env` on the VPS only after migrations succeed.
