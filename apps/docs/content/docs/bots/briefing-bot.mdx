## Overview

Briefing Bot combines persisted watcher events with weather, Google Calendar,
stock earnings, goals, and optional Notion journal context. It asks Ollama for
one bounded spoken script, synthesizes it through Piper, and delivers audio plus
a compact Telegram index.

## Architecture and flow

<Mermaid
  label="Briefing generation and reflection workflow"
  chart={`flowchart LR
    A["Schedule, manual command, or test"] --> B["Claim one briefing run"]
    B --> C["Load contexts in parallel"]
    C --> C1["Weather and Calendar"]
    C --> C2["Stocks, goals, and events"]
    C --> C3["Previous-day journal context"]
    C1 --> D["Cluster and rank persisted events"]
    C2 --> D
    C3 --> D
    D --> E["Generate validated spoken script"]
    E --> F["Piper speech synthesis"]
    F --> G["Idempotent Telegram audio and index"]
    H["Reflection answer"] --> I["Persist question state immediately"]
    I --> J{"More questions?"}
    J -->|Yes| H
    J -->|No| K["Complete original journal date"]`}
/>

`BriefingCoordinator` loads independent contexts in parallel, clusters and ranks
persisted events, calls `BriefingScriptGenerator`, then passes the script through
Piper and the idempotent delivery service. Scheduled, manual, and test runs share
this path. Optional context failures degrade the run without cancelling the
remaining briefing.

The journal stores resumable question state immediately. An active reflection
continues across midnight under its original journal date and takes precedence
over a newly initialized daily reminder. Voice input is transcribed in memory
and shown as an editable preview before confirmation.
Morning journal context is read from the previous Prague calendar day and is
never logged or persisted by the briefing path.

## Execution and scheduling

```bash
pnpm --filter @watcher/briefing-bot dev
pnpm --filter @watcher/briefing-bot typecheck
pnpm exec vitest run apps/briefing-bot/src/__tests__
```

The scheduler polls persisted configuration, enforces a maximum delay window,
and uses the same coordinator as manual commands. Evening planning and journaling
default to 21:00 in `Europe/Prague`. The daily goal review always precedes the
existing journal; weekly review waits for both, and a same-day monthly review
also waits for the weekly review.

## Troubleshooting

- A startup credential-group error means all values in that optional group must
  be set together or removed together.
- Calendar is optional. No connected token is shown as disabled; only an actual
  provider error is shown as unavailable.
- A missing journal row is omitted; duplicate dates are rejected as ambiguous.
- If voice journaling is unavailable, set an OpenAI-compatible transcription URL
  or use text input.
- If audio fails, verify Piper data, Python, FFmpeg, voice files, and writable
  temporary storage before changing LLM settings.
