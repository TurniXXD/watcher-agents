## Overview

Study Bot accepts text-based university PDFs, stores the source in S3-compatible
storage, extracts page text, creates cited facts through the shared Ollama queue,
writes a spoken lecture, synthesizes OGG/Opus audio with Piper, and returns a
Telegram voice message. Completion actions can resend audio, summarize, quiz, or
export an Anki-compatible UTF-8 TSV deck. Optional book commands read the
operator's Notion `Learning/Books` data source and create a book only after an
owner-bound Telegram confirmation.

## Commands and actions

| Command/action             | What it does                                                    |
| -------------------------- | --------------------------------------------------------------- |
| Upload a PDF               | Validates and starts a source-grounded study job.               |
| `/start`                   | Initializes the bot and shows the guide.                        |
| `/help`                    | Shows all commands and upload instructions.                     |
| `/about`                   | Explains storage, grounding, processing, and safety boundaries. |
| `/status`                  | Reports the latest document job and error, if any.              |
| `/cancel`                  | Cancels the latest active job at the next safe stage boundary.  |
| `/book_add TITLE`          | Looks up metadata and asks before writing the book to Notion.   |
| `/books`                   | Lists the current Notion book library.                          |
| `/books_category CATEGORY` | Lists books in one current category.                            |
| `/books_author AUTHOR`     | Lists books matching an author name.                            |
| `/books_next`              | Lists books whose `Next to read` checkbox is enabled.           |
| `/books_favorites`         | Lists books whose `Oblíbená` checkbox is enabled.               |
| `/books_categories`        | Lists supported Notion category options.                        |
| `/books_authors`           | Lists author values currently used by books.                    |
| Completion buttons         | Resend the lecture, create a summary/quiz, or export Anki TSV.  |

## Architecture and flow

<Mermaid
  label="Study document processing and delivery workflow"

The job validates file bounds, stores the original, extracts page text, rejects
scanned/near-empty documents, chunks evidence, coordinates Ollama work, creates
cited output, synthesizes media, persists progress, and delivers through
Telegram. Generated questions and cards retain page citations.

For `/book_add`, Study Bot queries structured Open Library search metadata,
validates it, maps categories and genre to the existing Notion options, and
stores a 30-minute confirmation draft in PostgreSQL. The confirmation callback
re-checks both the Telegram user and chat, claims the draft atomically, checks
for an exact-title duplicate, and only then writes the page. A Notion failure
returns the draft to a retryable state. Notion remains authoritative for saved
books.

## Execution and scheduling

```bash
pnpm --filter @watcher/study-bot dev
pnpm --filter @watcher/study-bot typecheck
pnpm exec vitest run apps/study-bot/src/__tests__
```

Jobs are upload-triggered rather than scheduled. Cancellation is cooperative at
safe stage boundaries.

## Integrations

Telegram receives uploads and returns output. S3-compatible storage keeps source
documents and media. pdf.js extracts text. Ollama and the shared queue generate
grounded study content. Piper provides speech. Open Library provides public,
structured book metadata with a bounded timeout; Notion stores the confirmed
book library. Neither integration is used for replacement PDF facts.

The book data source must expose `Kniha`, `Autor`, `Kategorie`, `Žánr`, `Stran`,
`Složitost`, `Poznámka`, `Přidáno`, plus boolean `Priorita`, `Přečteno`,
`Next to read`, and `Oblíbená`. New imports leave all boolean flags disabled so
the operator retains control in Notion.

## Troubleshooting

- OCR-required means the PDF has insufficient extractable text; preprocess it
  with OCR before retrying.
- S3 failures require checking endpoint, bucket names, credentials, and prefix
  permissions without logging secrets.
- A cancelled job may finish its current atomic stage before stopping.
- Missing audio usually points to Piper voice/runtime configuration after the
  text stages have succeeded.
- Book commands report unavailable when both Notion variables are empty; a
  partial Notion configuration fails environment validation at startup.
- Open Library can return incomplete metadata. Review the confirmation preview
  and correct category, genre, or page count in Notion after saving if needed.
- Expired, cancelled, already-used, or cross-user confirmation callbacks cannot
  write a book.
