## Overview

Study Bot accepts text-based university PDFs, stores the source in S3-compatible
storage, extracts page text, creates cited facts through the shared Ollama queue,
writes a spoken lecture, synthesizes OGG/Opus audio with Piper, and returns a
Telegram voice message. Completion actions can resend audio, summarize, quiz, or
export an Anki-compatible UTF-8 TSV deck.

## Commands and actions

| Command/action     | What it does                                                    |
| ------------------ | --------------------------------------------------------------- |
| Upload a PDF       | Validates and starts a source-grounded study job.               |
| `/start`           | Initializes the bot and shows the guide.                        |
| `/help`            | Shows all commands and upload instructions.                     |
| `/about`           | Explains storage, grounding, processing, and safety boundaries. |
| `/status`          | Reports the latest document job and error, if any.              |
| `/cancel`          | Cancels the latest active job at the next safe stage boundary.  |
| Completion buttons | Resend the lecture, create a summary/quiz, or export Anki TSV.  |

## Architecture and flow

The job validates file bounds, stores the original, extracts page text, rejects
scanned/near-empty documents, chunks evidence, coordinates Ollama work, creates
cited output, synthesizes media, persists progress, and delivers through
Telegram. Generated questions and cards retain page citations.

## Configuration

| Variable                                                                      | Required/default                | Purpose                                         |
| ----------------------------------------------------------------------------- | ------------------------------- | ----------------------------------------------- |
| `DATABASE_URL`                                                                | Required                        | PostgreSQL document/job state.                  |
| `STUDY_TELEGRAM_TOKEN`                                                        | Required                        | Dedicated Telegram token.                       |
| `TELEGRAM_ALLOWED_USER_IDS`                                                   | Required                        | Authorized uploaders.                           |
| `OLLAMA_URL`, `OLLAMA_MODEL`                                                  | Required                        | Grounded content generation.                    |
| `OLLAMA_MAX_CONCURRENCY`                                                      | Configured default              | Shared inference queue concurrency.             |
| `STUDY_OLLAMA_TIMEOUT_MS`, `STUDY_OLLAMA_NUM_CTX`, `STUDY_OLLAMA_NUM_PREDICT` | Bounded defaults                | Study-specific request limits.                  |

| `STUDY_S3_ACCESS_KEY_ID`, `STUDY_S3_SECRET_ACCESS_KEY`                        | Required                        | Application-specific S3 credentials.            |
| `STUDY_S3_DOCUMENTS_BUCKET`, `STUDY_S3_MEDIA_BUCKET`                          | Required                        | Source-document and generated-media buckets.    |
| `STUDY_S3_FORCE_PATH_STYLE`                                                   | Configured default              | Enables path-style S3 addressing when required. |
| `STUDY_MAX_PDF_SIZE_MB`, `STUDY_MAX_DOCUMENT_PAGES`                           | Bounded defaults                | Upload and document limits.                     |
| `STUDY_TTS_PROVIDER`, `STUDY_TTS_VOICE`                                       | `piper`, configured Czech voice | Speech provider and voice.                      |

## Execution and scheduling

```bash
pnpm --filter @watcher/study-bot dev
pnpm --filter @watcher/study-bot typecheck
pnpm exec vitest run apps/study-bot/src/__tests__
```

Jobs are upload-triggered rather than scheduled. Cancellation is cooperative at
safe stage boundaries.

## Integrations

Telegram receives uploads and returns output. S3-compatible storage keeps source
documents and media. pdf.js extracts text. Ollama and the shared queue generate
grounded study content. Piper provides speech.

## Troubleshooting

- OCR-required means the PDF has insufficient extractable text; preprocess it
  with OCR before retrying.
- S3 failures require checking endpoint, bucket names, credentials, and prefix
  permissions without logging secrets.
- A cancelled job may finish its current atomic stage before stopping.
- Missing audio usually points to Piper voice/runtime configuration after the
  text stages have succeeded.
