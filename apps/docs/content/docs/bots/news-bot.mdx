## Overview

News Bot monitors built-in and custom RSS/Atom feeds, normalizes and deduplicates
entries, applies structured significance/relevance analysis, filters disabled
categories, and publishes durable `news` events for Briefing. Topics start empty
and steer relevance without being presented as sourced facts.

## Commands

| Command                                                                    | What it does                                           |
| -------------------------------------------------------------------------- | ------------------------------------------------------ |
| `/start`                                                                   | Initializes the bot and shows the command guide.       |
| `/help`                                                                    | Shows every command and profile name.                  |
| `/about`                                                                   | Explains the bot, data flow, sources, and limitations. |
| `/feeds`                                                                   | Lists built-in and custom feeds with IDs.              |
| `/feed_add PROFILE URL [NAME]`                                             | Adds a validated custom RSS/Atom feed.                 |
| `/feed_remove ID`                                                          | Deletes a custom feed.                                 |
| `/feed_enable ID` / `/feed_disable ID`                                     | Enables or disables a feed without deleting it.        |
| `/topics`                                                                  | Lists relevance topics for both profiles.              |
| `/topic_add PROFILE TOPIC` / `/topic_remove PROFILE TOPIC`                 | Adds or removes a ranking topic.                       |
| `/categories`                                                              | Lists enabled and disabled categories.                 |
| `/category_enable PROFILE CATEGORY` / `/category_disable PROFILE CATEGORY` | Controls delivery for one category.                    |
| `/run [PROFILE]`                                                           | Runs both profiles or only `czech`/`global`.           |
| `/schedule [CRON] [TIMEZONE]`                                              | Shows or replaces the persisted schedule.              |
| `/pause` / `/resume`                                                       | Pauses or resumes scheduled runs.                      |
| `/status`                                                                  | Shows watcher and profile counts.                      |

## Architecture and flow

Feed adapters use safe HTTP behavior and validate redirects against private,
loopback, link-local, and unsafe targets. Entries normalize into the common
watcher shape before deduplication and bounded Ollama analysis. Useful events are
persisted for downstream Briefing consumption.

## Configuration

| Variable                                                    | Required/default       | Purpose                                   |
| ----------------------------------------------------------- | ---------------------- | ----------------------------------------- |
| `DATABASE_URL`                                              | Required               | PostgreSQL connection.                    |
| `NEWS_TELEGRAM_TOKEN`                                       | Required               | Dedicated Telegram token.                 |
| `TELEGRAM_ALLOWED_USER_IDS`                                 | Required               | Authorized private operators.             |
| `OLLAMA_URL`, `OLLAMA_MODEL`                                | Required               | Structured relevance analysis.            |
| `OLLAMA_KEEP_ALIVE`                                         | `5m`                   | Model residency hint.                     |
| `OLLAMA_MAX_ITEMS_PER_RUN`                                  | `0`                    | Optional analysis cap; zero is unlimited. |
| `OLLAMA_NUM_CTX`, `OLLAMA_NUM_PREDICT`                      | `4096`, `768`          | Context and output-token bounds.          |
| `OLLAMA_RETRIES`, `OLLAMA_THINK`, `OLLAMA_TIMEOUT_MS`       | `1`, `false`, `120000` | Retry, thinking, and timeout controls.    |
| `SOURCE_BACKOFF_BASE_SECONDS`, `SOURCE_BACKOFF_MAX_MINUTES` | `60`, `360`            | Feed failure backoff.                     |
| `SOURCE_MAX_CONCURRENCY`                                    | `8`                    | Maximum concurrent feed calls.            |
| `DEFAULT_TIMEZONE`                                          | `Europe/Prague`        | Initial schedule timezone.                |
| `LOG_LEVEL`                                                 | `info`                 | Structured log level.                     |

## Execution and scheduling

```bash
pnpm --filter @watcher/news-bot dev
pnpm --filter @watcher/news-bot typecheck
pnpm exec vitest run apps/news-bot/src/__tests__
```

Manual and persisted scheduled runs share the same pipeline. The Global profile
contains public news, science, technology, health, European, and space feeds;
retired Czech and GDELT-only entries remain disabled.

## Integrations

RSS/Atom feeds are primary. The enabled Global catalog covers major public news,
science, technology, health, European, and space feeds; custom operator feeds use
the same SSRF-safe adapter. PostgreSQL stores configuration, normalized items,
schedules, and events. Ollama adds validated relevance analysis; Telegram is the
private operator UI; Briefing Bot consumes durable `news` events.

## Troubleshooting

- A custom feed rejection usually means an invalid URL, unsafe destination, or
  redirect.
- An empty topic list is valid but provides no operator-specific relevance cue.
- Inspect per-source health before changing global concurrency.
- Scheduled empty results are intentionally silent; use `/run` for explicit
  confirmation.
