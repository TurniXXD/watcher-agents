## Overview

Reality Bot monitors Czech property listings and produces periodic reports or
alerts only when persisted yield, discount, and cashflow gates pass. It models
purchase price, equity, mortgage terms, vacancy, maintenance, insurance, yields,
annuity payments, and stress cashflows.

## Commands

| Command                                        | What it does                                                  |
| ---------------------------------------------- | ------------------------------------------------------------- |
| `/start`                                       | Initializes settings and shows the guide.                     |
| `/help`                                        | Shows all commands.                                           |
| `/about`                                       | Explains the model, data domains, and investment limitations. |
| `/status`                                      | Shows state, locations, schedule, and last run.               |
| `/run`                                         | Fetches listings and sends a market report now.               |
| `/pause` / `/resume`                           | Disables or enables reports and alerts.                       |
| `/schedule CRON TIMEZONE`                      | Replaces the monthly report schedule.                         |
| `/locations`                                   | Lists monitored locations.                                    |
| `/location_add CITY` / `/location_remove CITY` | Adds or removes a location.                                   |
| `/model`                                       | Shows the mortgage and operating-cost model.                  |
| `/model PRICE EQUITY_% YEARS VACANCY_%`        | Updates the principal assumptions.                            |

## Architecture and flow

DigiReality RSS records are validated, normalized, cached, and persisted with
listing history. Historical observations support measured discount and
time-on-market calculations. Photographs are not downloaded; malformed listings
are dropped instead of repaired with guesses.

## Configuration

| Variable                           | Required/default             | Purpose                                             |
| ---------------------------------- | ---------------------------- | --------------------------------------------------- |
| `DATABASE_URL`                     | Required                     | PostgreSQL connection and durable settings/history. |
| `REALITY_TELEGRAM_TOKEN`           | Required                     | Dedicated Telegram token.                           |
| `TELEGRAM_ALLOWED_USER_IDS`        | Required                     | Authorized private operators.                       |
| `REALITY_DIGIREALITY_KEY`          | Optional                     | Optional DigiReality access key.                    |
| `REALITY_DEFAULT_LOCATIONS`        | `Brno,Ostrava,Frýdek-Místek` | Initial location list.                              |
| `REALITY_REPORT_SCHEDULE`          | `0 8 1 * *`                  | Default monthly report cron.                        |
| `REALITY_MONITOR_INTERVAL_MINUTES` | `30`                         | Listing polling interval.                           |
| `REALITY_HEALTH_PORT`              | `4050`                       | Private readiness port.                             |
| `DEFAULT_TIMEZONE`                 | `Europe/Prague`              | Schedule timezone.                                  |
| `LOG_LEVEL`                        | `info`                       | Structured log level.                               |

## Execution and scheduling

```bash
pnpm --filter @watcher/reality-bot dev
pnpm --filter @watcher/reality-bot typecheck
pnpm exec vitest run apps/reality-bot/src/__tests__
```

Monitoring defaults to every 30 minutes. The report schedule defaults to 08:00
on the first day of each month. Telegram changes persist in PostgreSQL.

## Integrations

The current listing source is DigiReality RSS. PostgreSQL stores models,
locations, listing history, schedules, and alerts. Telegram provides all
operator actions.

## Troubleshooting

- Missing source fields are not inferred; inspect the dropped-listing log.
- Discount and time-on-market require prior persisted observations.
- If no alerts arrive, review model thresholds and configured locations before
  changing the monitor cadence.
- A missing optional DigiReality key may reduce access but should not be replaced
  with scraped credentials.
